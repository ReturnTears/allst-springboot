# 自动配置

设备接入不是写在启动类上的 `@Bean` 方法里，而是走 Spring Boot 3 的自动配置入口，这样以后把 `com.allst.netty` 挪到独立 starter 时，启动类不用改。

## 装入方式

启动类在 `com.allst.springboot`，组件扫描到不了 `com.allst.netty`。

`src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 只有一行：

```text
com.allst.netty.autoconfigure.NettyGatewayAutoConfiguration
```

`AutoConfigurationImportSelector` 会从 classpath 上每个 jar（包括应用自己的 `target/classes`）读取这个文件。`@AutoConfiguration(after = JacksonAutoConfiguration.class)` 保证创建编解码器时，Spring Boot 的 `ObjectMapper` 已经存在。编解码器直接注入这个 `ObjectMapper`，不再自己 new 一个，HTTP 和 TCP 的 JSON 行为一致。

应用自己的 imports 和依赖 jar 里的 imports 用的是同一套机制。差别只是现在还放在这一个模块里。

## 条件

`NettyGatewayAutoConfiguration` 上有 `@ConditionalOnClass(ServerBootstrap.class)`。没有 Netty 时整段配置不加载。当前 Netty 由 WebFlux 传递进来，这个条件是文档化的保险，不是可选依赖。

`@EnableConfigurationProperties` 注册三个配置类，即使对应的服务器被关掉，配置对象仍在，启动日志和 `/api/meta` 还能读到路径和开关。

| Bean | 条件 |
| --- | --- |
| 编解码器、会话表、扫码日志、指令表、推送服务 | 缺少同类型 Bean 时创建 |
| `WarehouseServerHandler`、`NettyTcpServerLifecycle` | `netty.server.enabled=true`，缺省即开启 |
| 看板 Handler 和生命周期 | `netty.websocket.enabled=true`，缺省即开启 |
| `DeviceSimulator` | `netty.client.enabled` 和 `netty.client.simulator-enabled` 都为 true，缺省都开启 |

两个客户端开关写在同一个 `@ConditionalOnProperty` 的 `name` 数组里。Spring Boot 要求数组中的每一项都匹配 `havingValue`，缺省时 `matchIfMissing` 视为匹配。因此只把 `simulator-enabled` 设为 false 时，枪不会自动拨号，但 HTTP 和 TCP 服务仍在。`WarehouseGatewayTest` 用的就是这个开关，并断言 `/api/meta` 里 `simulatorEnabled` 为 false。

`@ConditionalOnMissingBean` 让测试或以后的业务模块可以自己提供同类型 Bean，自动配置会退开。

配置类使用 setter 绑定，而不是单个全参构造。这样 YAML 可以只改一个字段。三个 Properties 类都标了 `@Validated`，端口、线程数、帧长不合法时应用会在启动期失败，而不是等到第一台枪连上来。

## 和 WebFlux 自动配置的对照

| | 设备接入 | WebFlux HTTP |
| --- | --- | --- |
| 注册位置 | 应用内的 `AutoConfiguration.imports` | `spring-boot-autoconfigure` 自带的 imports |
| 配置类 | `NettyGatewayAutoConfiguration` | `ReactiveWebServerFactoryAutoConfiguration` |
| 选中的服务器 | 自己 new `NioEventLoopGroup` | `EmbeddedNetty` 注册 `NettyReactiveWebServerFactory` |
| 关闭方式 | 对应的 `enabled=false` | 去掉 `spring-boot-starter-webflux`，或改用别的 `ReactiveWebServerFactory` |

两边都是「classpath 上有什么、属性是什么，就装配什么」，没有在 `main` 方法里手写 `bind`。

## 抽成 starter 时要带走的东西

- `com.allst.netty` 整个包
- `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
- 对 `spring-boot-autoconfigure`、Netty、Jackson、Reactor Core 的依赖

`com.allst.springboot.warehouse` 留在业务应用里。它只依赖会话表、推送服务和生命周期这些 Bean，不关心线程组是在哪一行创建的。
