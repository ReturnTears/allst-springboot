# 02 持久化建模

表结构以 `src/main/resources/sql/bootstrap.sql` 为准。JPA 不负责建表，`spring.jpa.hibernate.ddl-auto=none`。

原有的 `init.sql` 仍保留。它里面有 `DELETE`，不适合反复执行，所以启动数据改走 `bootstrap.sql`。

## 表

| 表 | 作用 | 来源 |
| --- | --- | --- |
| `book` | 书名、页数 | 原示例 |
| `author` | 作者，`bookId` 指向书，删除书时级联删除作者 | 原示例 |
| `category` | 分类 | 新增 |
| `book_category` | 一本书最多一个分类 | 新增 |
| `reader` | 读者 | 新增 |
| `membership` | 读者对某本书的订阅 | 新增 |

`book`、`author` 继续用原来的驼峰列名（`pageCount`、`firstName`）。新表用下划线列名，并在实体上写明 `@Column(name = "...")`。当前命名策略是 `PhysicalNamingStrategyStandardImpl`，不会自动把驼峰改成下划线，所以列名必须写清楚。

新实体都标了 `schema = "demo"`，和原来的 `Book`、`Author` 一致。

## 约束

- 书名、分类名、读者姓名、读者邮箱唯一。
- 读者状态只有 `ACTIVE`、`DISABLED`。
- 订阅方案只有 `MONTHLY`、`QUARTERLY`、`YEARLY`，状态只有 `ACTIVE`、`PAUSED`、`CANCELLED`、`EXPIRED`。枚举以字符串入库。
- `membership.reader_id`、`membership.book_id` 有外键。有订阅的书不能直接删掉。
- 价格和截止日期在写入时按方案算好再落库，不在查询时现算。

方案对应关系写在 `MembershipPlan` 里：

| 方案 | 天数 | 价格 |
| --- | --- | --- |
| 月订 | 30 | 18 |
| 季订 | 90 | 48 |
| 年订 | 365 | 168 |

## 时间

`reader.created_at`、`membership.created_at` 用 `LocalDateTime`。订阅起止日期用 `LocalDate`。`@PrePersist` 会在插入时补上创建时间。更新时创建时间字段标记了 `updatable = false`。

Hibernate 时区设为 `Asia/Shanghai`，和 JDBC URL 里的 `GMT+8` 对齐，避免日期时间被挪几个小时。
