# 09 错误处理

业务规则不满足时抛 `BusinessException`，带一个稳定的 `code` 和给页面看的中文说明。

| code | 何时使用 |
| --- | --- |
| `BAD_REQUEST` | 缺字段、格式不对、超长 |
| `NOT_FOUND` | 按编号找不到 |
| `CONFLICT` | 重名、重复订阅、停用读者仍要订阅 |
| `REFERENCED` | 删除时仍被别的记录引用 |
| `INTERNAL` | 没有归类的异常。详细堆栈只打日志，不返回给客户端 |

`graphql.servlet.exception-handlers-enabled=true` 已经打开。`GraphqlExceptionAdvice` 用 `@ExceptionHandler` 把异常收成 GraphQL 错误：

```json
{
  "errors": [
    {
      "message": "该读者对这本书已有进行中的订阅",
      "extensions": { "code": "CONFLICT" }
    }
  ],
  "data": { "createMembership": null }
}
```

另外两种异常也收进来了：

- 原来的 `AuthorService` 找不到作者时抛的 `EntityNotFoundException`，映射为 `NOT_FOUND`。
- 数据库唯一约束或外键失败，映射为固定的 `REFERENCED` 说明，不把 SQL 返回给页面。
- 其他未归类异常记日志，并返回 `INTERNAL` / “服务处理失败”。

事务方法抛出未捕获的运行时异常时，Spring 会回滚。重复订阅这种失败不会留下半条记录。
