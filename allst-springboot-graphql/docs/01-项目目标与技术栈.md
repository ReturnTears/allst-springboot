# 01 项目目标与技术栈

这个模块用来约定一件事：Spring Boot 项目里 GraphQL 怎么分层，而不是只停在一个能查出书名的示例上。

场景是一个图书订阅台。读者按月、按季或按年订阅架上的书。管理员可以维护书目、作者、分类、读者和订阅。

## 保留的原示例

这些文件保持原来的职责，没有改写业务逻辑：

- `books.graphqls` 里的 `Book`、`Author`、`findAll`、`newBook`、`deleteBook`、`updateAuthor`
- `BookQuery`、`BookMutation`、`AuthorQuery`、`AuthorMutation`、`BookAuthorResolver`
- `BookController` 上的 REST 查询
- `HelloWorld`：不启动 Spring，直接用代码拼一个 schema 的最小例子

新能力写在 `com.allst.boot.subscription`，通过 `extend type` 接到原来的 `Query`、`Mutation` 和 `Book` 上。

## 技术栈

模块的 `pom.xml` 把 `spring-boot-starter-*` 写成 2.7.4。父工程 `allst-springboot` 的 BOM 是 Spring Boot 2.6.5，Maven 以父工程的版本管理为准，所以启动横幅会显示 2.6.5。Kickstart 14 在这个运行版本上可用，接口行为按本文档为准。

| 层 | 选择 |
| --- | --- |
| 语言 | Java 11（本机用 JDK 17 编译到 11） |
| 框架 | starter 声明 2.7.4，实际随父工程 BOM 运行为 2.6.5 |
| GraphQL | graphql-java-kickstart 14.0.0，schema 优先 |
| 持久化 | Spring Data JPA，`ddl-auto=none` |
| 数据库 | MySQL 8，库名 `demo`，用户 `root`，密码为空 |
| 前端 | Vue 3 + Vue Router + Vite，自己发 GraphQL HTTP |

Kickstart 用的是 schema 优先：先写 `.graphqls`，再写实现了 `GraphQLQueryResolver`、`GraphQLMutationResolver`、`GraphQLResolver`、`GraphQLSubscriptionResolver` 的 Spring Bean。方法名和参数名要和 schema 一致，所以编译打开了 `-parameters`。

`HelloWorld` 则是另一条路：代码里写 schema 字符串，适合理解 GraphQL Java 本身，不作为这个 Web 项目的主路径。

## 包怎么放

原代码按技术层分包：`model`、`repository`、`queryresolvers`。新代码按业务放在 `subscription` 下，再分 `model`、`repository`、`service`、`graphql`。解析器只做参数转发，规则放在 `service`。
