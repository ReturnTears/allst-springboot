# 06 字段解析与嵌套

有些 GraphQL 字段不是表上的列。它们用 `GraphQLResolver<父类型>` 单独解析，避免把关联对象直接塞进实体，也避免一个根查询类越来越大。

| 父类型 | 字段 | 类 |
| --- | --- | --- |
| `Book` | `author` | 原来的 `BookAuthorResolver` |
| `Book` | `category` | `BookCategoryFieldResolver` |
| `Category` | `bookCount` | `CategoryFieldResolver` |
| `Reader` | `memberships` | `ReaderFieldResolver` |
| `Membership` | `reader`、`book` | `MembershipFieldResolver` |

同一个 Java 类型可以有多个字段解析器。`Book` 的作者和分类就是这样拆开的，原来的作者解析器不用改。

客户端决定要不要这些字段。不查询 `author`，就不会执行 `BookAuthorResolver`。

```graphql
query {
  memberships(page: { page: 1, size: 5 }) {
    items {
      plan
      status
      reader { username status }
      book {
        name
        author { firstName lastName }
        category { name }
      }
    }
  }
}
```

根字段 `readerMemberships(readerId)` 和 `Reader.memberships` 都能拿到某个读者的订阅。前者适合已知读者编号的页面；后者适合从读者对象往下展开。订阅台的读者页用的是前者。

新的关联字段走 DataLoader，同一次请求里相同的加载会合并成一批查询。原来的 `Book.author` 仍是一本一查，用来对照。见[DataLoader](10-DataLoader.md)。
