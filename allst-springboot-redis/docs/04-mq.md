# 04 消息队列

代码：`mq/MqService`、`mq/ListQueueConsumer`、`mq/StreamQueueConsumer`。

Redis 可以做轻量队列。要求消息不能丢、消费组、死信堆积时，仍然应该用专门的消息中间件。这里演示两种够用的做法。

## List

生产者 `LPUSH mq:list:email`。消费者 `RPOPLPUSH` 到 `mq:list:email:processing`，这一步是原子的。处理成功后 `LREM` 掉处理中的那条，并把原文放进结果列表。

进程如果在挪走之后、确认之前停掉，消息会留在 processing 列表里，可以查出来再入队。主题以 `fail` 开头的邮件会进 `mq:list:email:dead`，用来看失败分支。

这是至少一次投递的雏形，不是精确一次。消费者要能接受重复消息。

## Stream

`XADD mq:stream:email`。启动时 `XGROUP CREATE ... MKSTREAM`，组名 `email-group`。消费者用 `XREADGROUP` 读取还没投递过的新消息，处理完 `XACK`。

Redis 5 没有 `MKSTREAM` 时，代码会先写一条占位消息再创建消费组。

未确认消息留在 PEL 里。示例为了不让坏消息堵住组，失败也会确认并写入死信。生产上应先重试，再用 `XAUTOCLAIM` 把超时消息交给其它消费者。当前读取没有 `BLOCK`，由调度线程每秒拉一次，避免占住 Lettuce 连接。

## 接口

- `POST /api/mq/list` 和 `POST /api/mq/stream`，体：`{"to":"ada","subject":"欢迎","body":"你好"}`
- `GET /api/mq/list`
- `GET /api/mq/stream`

## 验证

发送一封普通邮件，一两秒后在对应的结果列表里能看到。主题写成 `fail`，它会出现在 dead 列表。
