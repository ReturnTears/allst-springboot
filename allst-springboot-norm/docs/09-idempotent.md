# 9. 幂等

创建用户、批量创建用户、创建订单、批量创建订单要求 `X-Idempotent-Key`。网络重试不会插入第二行。

## 实现

| 类 | 作用 |
| --- | --- |
| `@Idempotent` | 标在控制器方法上 |
| `IdempotentAspect` | 抢占记录、缓存成功响应、失败时删除记录 |
| `IdempotentRecord` | 表 `norm_idempotent`，`idem_key` 唯一 |

幂等键规则：8 到 64 位字母、数字、下划线或中划线。库里的唯一键是 `appId:幂等键`。

处理过程：

1. 已有成功记录，并且接口相同：返回第一次的 HTTP 状态和 body。
2. 已有成功记录，但接口不同：`40901`，提示幂等键已被其他接口使用。
3. 记录仍是处理中，且未超过 `norm.idempotent.processing-timeout-seconds`（默认 120 秒）：`40903`。
4. 处理中已超时：删掉旧记录，本次返回 `40903`，调用方用同一把钥匙再试一次。
5. 本次执行抛错：删除记录，调用方可以重试。
6. 两个请求同时插入：数据库唯一约束只让一个成功，另一个走上面的已有记录逻辑。

限流在幂等之前。被限流的请求不会留下处理中记录。

参数校验发生在进入业务方法之前，校验失败不会占用幂等键。

幂等键参与签名，见 [01-signature.md](01-signature.md)。

## 调用约定

创建类请求每次业务动作使用一把新钥匙。超时重试必须沿用同一把钥匙，同时使用新的 `X-Nonce` 和新的时间戳，并重新计算签名。
