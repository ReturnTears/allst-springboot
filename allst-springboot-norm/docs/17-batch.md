# 17. 批量操作

多条数据一次提交，在一个事务里全部成功或全部回滚，避免调用方循环单条接口把耗时和失败处理摊开。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/users/batch` | 批量创建用户，需要幂等键 |
| DELETE | `/api/v1/users/batch` | 批量删除用户，body 为 `{ "ids": [1, 2] }` |
| POST | `/api/v1/orders/batch` | 批量创建订单，需要幂等键 |

上限默认 100，配置项 `norm.batch.max-size`。列表上的 `@BatchLimited` 和服务里的 `SizeGuard` 都会检查。

批量创建用户时：

- 请求内部出现重复用户名，整批失败。
- 任一用户名已经存在，整批失败，消息带上冲突的用户名。
- 全部通过后一次 `saveAll`，事务提交后再逐条发异步通知。

批量删除时，只要有一个编号不存在，整批取消，已存在的记录也不会被删掉。

批量创建订单时，只要有一个用户不存在，整批订单都不创建。

单条创建和批量创建是两个接口。批量接口的校验、上限和事务边界集中在批量方法里，不把循环塞进单条接口。
