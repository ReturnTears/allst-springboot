# 02 环境准备

## 版本

| 项 | 版本 | 原因 |
| --- | --- | --- |
| JDK | 11 | 与父工程一致 |
| Spring Boot | 2.6.5 | 父 POM `spring-boot-dependencies` |
| Canal | 1.1.7 | 官方镜像 `canal/canal-server:v1.1.7`，客户端 `com.alibaba.otter:canal.client` |
| Elasticsearch | 7.17.18 | Boot 2.6 的 `RestHighLevelClient` 属于 7.x，不能接 ES 8 |
| RabbitMQ | 3.13 management | 需要管理台看队列和死信 |
| MongoDB | 6.0 | 文档型下游 |
| Redis | 7.2 | Hash 缓存 |

依赖在模块 `pom.xml`。父工程 `pom.xml` 已加入模块 `allst-springboot-canal`。

## 端口

| 服务 | 宿主机端口 | 说明 |
| --- | --- | --- |
| 本应用 | 1238 | `application.yml` |
| MySQL | 3306 | 根密码 `root`，库 `demo` |
| Canal | 11111 | destination 名 `example` |
| RabbitMQ | 5672 / 15672 | 账号 `guest` / `guest`，管理台 `http://127.0.0.1:15672` |
| Redis | 6379 | 无密码 |
| MongoDB | 27017 | 库名 `canal_sync` |
| Elasticsearch | 9200 | 安全认证关闭 |

本机这些端口已被占用时，只改 `deploy/docker-compose.yml` 左侧宿主机端口，以及 `application.yml` 里对应地址。Canal 容器访问 MySQL 用的是 compose 网络里的 `mysql:3306`，不要改成宿主机映射端口。

## 启动中间件

在模块目录执行：

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Elasticsearch 在 Docker Desktop 上如果立刻退出，多半是虚拟内存不够。在 WSL 里执行：

```bash
sysctl -w vm.max_map_count=262144
```

然后 `docker compose -f deploy/docker-compose.yml up -d elasticsearch`。

看状态：

```bash
docker compose -f deploy/docker-compose.yml ps
```

`mysql` 要变成 healthy，`canal-server` 才启动。Canal 日志：

```bash
docker logs allst-canal-server
```

出现 `start successful` 且 destination `example` 没有反复报连不上 MySQL，就可以启动应用。

## 启动应用

```bash
mvn spring-boot:run
```

或在 IDE 里运行 `AllstSpringbootCanalApplication`。

先确认进程起来了，这时三个下游可以还没有这份数据：

```text
GET http://localhost:1238/api/sync/ping
```

返回里 `redis`、`elasticsearch`、`mongodb` 都应为 `true`。

## 关掉某一路

`application.yml`：

```yaml
sync:
  redis:
    enabled: false
```

`false` 时不声明对应队列的绑定，也不创建消费者。另外两路继续工作。Canal 客户端用 `canal.client.enabled=false` 关掉后，应用只消费已经在 MQ 里的消息。

## 清空重来

`deploy/mysql/init.sql` 只在 MySQL 数据卷第一次初始化时执行。改过建表脚本后需要删卷：

```bash
docker compose -f deploy/docker-compose.yml down -v
docker compose -f deploy/docker-compose.yml up -d
```

这会清掉 MySQL、Canal 位点和三个下游里本次实验的数据。
