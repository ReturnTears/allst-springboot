# 08 联调验证

按这个顺序做。前面的服务没起来就执行 SQL，变更不会出现在三个下游里。

## 1. 中间件

```bash
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml ps
```

MySQL 为 healthy。Canal 日志里 destination `example` 已启动：

```bash
docker logs allst-canal-server
```

## 2. 应用

```bash
mvn spring-boot:run
```

```text
GET http://localhost:1238/api/sync/ping
```

`redis`、`elasticsearch`、`mongodb` 均为 `true`。应用日志有 `已连接 Canal 127.0.0.1:11111, destination=example`。

RabbitMQ 管理台 `http://127.0.0.1:15672`（guest / guest）里应能看到 `canal.sync.exchange` 和三条工作队列。队列是应用启动时声明的，只起中间件、不起应用时还没有这些队列。

## 3. 写入一行

PowerShell：

```powershell
Get-Content deploy\mysql\verify.sql | docker exec -i allst-canal-mysql mysql -uroot -proot
```

bash：

```bash
docker exec -i allst-canal-mysql mysql -uroot -proot < deploy/mysql/verify.sql
```

脚本插入 `id=1001`，再把它更新成名称 `Canal入门（修订）`、库存 18、价格 42.50。

应用日志里应先后出现 INSERT 和 UPDATE 的“已发布到 MQ”，以及三个“已写入”。

## 4. 对照

```text
GET http://localhost:1238/api/sync?schema=demo&table=t_product&id=1001
```

三份 `found` 都是 `true`。`name` 为 `Canal入门（修订）`，`stock` 为 `18`。三份 `_binlogOffset` 相同，并且是 UPDATE 那条，不是 INSERT 那条。INSERT 的位点更小，会被 UPDATE 覆盖。

如果某一端 `found=false`：

- 看该队列是否还有 Ready 消息，说明消费者还没处理完。
- 看对应死信队列和日志 `同步失败进入死信队列`。
- ES 第一次写入后立即查询仍为空时，确认日志里是“已写入”而不是连接被拒绝。写入已经使用立即刷新。

## 5. 删除

PowerShell：

```powershell
docker exec -i allst-canal-mysql mysql -uroot -proot demo -e "DELETE FROM t_product WHERE id=1001;"
```

bash 同样可以使用上面这条命令。

再次调用同一个查询接口，三份 `found` 都应为 `false`。Redis key、ES 文档、MongoDB 文档都按主键删除。

## 6. 重复投递不会把新数据盖旧

这一步不用手工制造 Canal 重发。`BinlogCursorTest` 已经覆盖“同一文件更小偏移不应用”。联调时如果看到日志 `跳过更旧的变更`，说明迟到消息被丢掉了，接口里应仍是偏移更大的那一版。

## 常见故障

| 现象 | 先看 |
| --- | --- |
| Canal 一直重连，认证失败 | MySQL 用户是不是 `mysql_native_password`，密码是不是 `canal`。改过 init.sql 后有没有 `down -v` 重建数据卷 |
| Canal 连不上 mysql:3306 | 两个容器是否在同一个 compose 项目里。实例地址不要写成 127.0.0.1 |
| 应用连不上 11111 | `docker ps` 看 `allst-canal-server` 是否在听 11111。destination 必须是 `example` |
| SQL 执行了但 MQ 没有消息 | SQL 是不是在 Canal 和本应用启动之前执行的。那种变更不在当前位点之后 |
| 只有部分列被更新到 ES | MySQL `binlog_row_image` 必须是 FULL |
| ES 容器反复退出 | `vm.max_map_count`，见 [02-环境准备](02-环境准备.md) |
| 队列里有消息但下游没变化 | `sync.*.enabled` 是否为 false，或者死信队列里已经有失败消息 |
